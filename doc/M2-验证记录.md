## 2. 关键决策

- **进程与宿主解耦**：`detached: true`，宿主退出不影响游戏；停止用 `taskkill /PID <pid> /T /F` 杀整棵树。
- **重启对账不猜结局**：`pid` 还在就保留运行态，探不到就把状态标成 `unknown` 并记下结束时间——不伪造 `exited`。
- **一个工程一个实例**：服务端在 `start()` 里检查，界面只是把按钮禁用。并发时返回 `ALREADY_RUNNING` 并附上正在跑的记录。
- **启动前重新识别**：`launch.start` 会重新扫一次工程，`taskPath` 必须出现在识别结果里；任务路径还走 `^(:module:)*run\w+$` 白名单。界面上没有自由输入，但 API 是公开面。
- **工程必须落在工作区内**：`launch.start` 用路径前缀校验，跨出工作区直接拒绝。

## 5. 顺带修掉的编码问题

第一轮日志第一行是乱码：`.bat` 用 UTF-8 保存，而 `cmd.exe` 按 OEM 代码页（中文 Windows 是 GBK）读取。真实工程里同样会遇到 Gradle/游戏的 GBK 输出。

现在输出按**字节切行、逐行解码**：先 UTF-8，出现替换字符再回退 GBK。日志文件仍保留原始字节，读取时同样逐行解码。

## 6. 已知限制

1. **还没有真的起过一次 Minecraft 客户端**。M2 验证用假 gradlew 覆盖了进程、就绪、日志、停止；真实客户端的首次构建（下载依赖、几十分钟）留到桌面版试跑。
2. **就绪判定是日志特征匹配**：`Backend library: LWJGL` / `OpenAL initialized`。真实客户端若被模组改写日志，可能识别不到；此时状态停在 `starting` 并在界面标注"暂未看到就绪标记"，不会误报成功。
3. **`DEV_AUTO_OPEN` 仍开着**：没有会话时标题栏 slot 不渲染，M1/M2 都靠它自动打开详情标签。M3 关掉。
4. **每次启动都会重新识别**（约 100ms）：这是为了挡住伪造的 `taskPath`，代价可接受；工程很大时可以加缓存。
