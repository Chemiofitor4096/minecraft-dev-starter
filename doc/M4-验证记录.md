## 1. 这一版改了什么

| 位置 | 之前（M3） | 现在（M4） |
|---|---|---|
| 日志 | 详情页里一小段尾部 | 右侧栏独立「运行日志」标签 |
| 历史 | 无 | 下拉列出当前工程的实例，默认最新；关掉再开还回到上次那条 |

## 2. 归因规则

`diagnose()` 在日志尾部 300 行里按"越具体越先命中"的顺序匹配，返回 `{ hint, line }`：

| 特征 | 结论 |
|---|---|
| `Could not resolve` / `Could not find <坐标>:` | 依赖解析失败：检查网络或 Gradle 离线缓存 |
| `Unsupported class file major version` | JDK 版本不匹配 |
| `No matching toolchains found` | 缺少所需版本的 JDK |
| `Address already in use` / `FAILED TO BIND TO PORT` | 端口被占用 |
| `Mixin apply failed` | Mixin 注入失败 |
| `OutOfMemoryError` / `Metaspace` | 内存不足 |
| `crash-reports/` | 游戏生成了 crash report |
| `BUILD FAILED` | Gradle 构建失败 |

只有实例异常退出（`outcome !== normal`）时才给归因，正常退出不打扰。

## 3. 配置

宿主接受 patch 行的 `config`，客户端启动时用 `state.info` 取回：

| 键 | 默认 | 作用 |
|---|---|---|
| `autoOpenLogTab` | `true` | 启动成功后自动打开日志标签 |
| `readyTimeoutMs` | `90000` | 等就绪标记的上限（超时不判失败，只标注） |
| `logRingLines` | `2000` | 每个实例在内存里保留的行数 |

> 顺带确认：**插件不需要导出 schemastery 的 `Config`**。cordis 会把 patch 行的 `config` 原样传给 `apply(ctx, config)`；这样我们的包不必依赖 `@deepseek-ai/schemastery`（link: 安装时它解析不到）。

验证方式：在测试 profile 的 patch 里写 `autoOpenLogTab: false`，`state.info` 返回 `false`；改回 `[]` 后热重载生效、又变回 `true`。

## 6. 已知限制

1. **自动打开只在"从面板点启动"时触发**：AI 通过 `mc_launch` 起的实例不会替人切换标签（那是工具调用，不该抢界面）。M5 之后可考虑加配置放开。
2. **日志是全量重读**：每次轮询读整份文件再取前 800 行。文件很大（几十 MB）时会有开销；M5 之后可以改成按行偏移增量读文件。
3. **历史不跨工程**：标签只列当前工程的实例，换工程才看到别人的。
