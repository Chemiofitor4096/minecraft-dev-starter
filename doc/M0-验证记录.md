# M0 验证记录

> 日期：2026-10-30 · 结论：**通过**。客户端包能在真实运行时里加载、激活、注册标题栏 slot 与右侧栏标签，并能驱动 `openTab` 展开侧栏。
> 对应策划：`doc/策划.md` §12 M0、§12 里的"如果证伪就退回网页方案"。

---

## 1. 要验证什么

| 编号 | 假设 | 不成立的后果 |
|---|---|---|
| V1 | 宿主入口能被 profile 加载并注册 HTTP 路由 | 整个插件模型不成立 |
| V3 | 客户端包能被 `__ModuleLoader__` 收下并激活 | 标题栏胶囊做不出来，退回独立网页 |
| V3b | 能注册右侧栏标签类型 + 正文，且 `openTab` 会展开面板 | 日志没地方放 |
| V7 | 浏览器能同源打到宿主路由 | 界面拿不到状态 |

## 2. 环境

- 独立 profile：`~/.dsh/profiles/m0test`（`dsh --profile m0test --from-default-profile web` 创建）
- 端口：3499（避免和桌面 GUI 的 3458 冲突）
- 启动方式：`dsh --profile m0test --port 3499 --no-open`
- CLI：`@deepseek-ai/dsh@0.1.5-rc.1`（桌面版自带更新的运行时，M0 先在 CLI web profile 上验机制）

## 3. 复现步骤

```powershell
# 1. 建 profile（只需一次）
node <dsh>/lib/bin.js --profile m0test --from-default-profile web --port 3499 --no-open

# 2. 挂本地插件（link: 是为了改完即生效，file: 会被 pnpm 拷贝）
node <dsh>/lib/bin.js plugin --profile m0test add link:C:/Projects/minecraft-dev-starter

# 3. 起服务，浏览器打开它打印的带 token 的 URL
node <dsh>/lib/bin.js --profile m0test --port 3499 --no-open

# 4. 看客户端回传的探针结果
curl http://127.0.0.1:3499/mcdev/api/reports
```

注意：`plugin add` 会把包加进 `dsh.profile.bundles`，不需要手改 patch 文件。

## 4. 结果

宿主侧日志：

```
[mcdev] host half ready (0.0.1-m0) — GET /mcdev/api/ping
```

启动图（首页 HTML 里的 `/plugins` 行）确认包含我们的包：

```
{"id":"minecraft-dev-starter","url":"/plugins/??minecraft-dev-starter/client.js&rev=..."}
```

浏览器加载后，客户端回传：

```json
{"phase":"activate","capsule":"registered","tabType":"registered","tabBody":"registered"}
{"phase":"auto-open","ok":true,"expanded":false}
{"phase":"auto-open-late","expanded":true,"activeTab":{"id":"tab2","kind":"mcdev.logs","title":"运行日志"}}
```

| 编号 | 结果 | 证据 |
|---|---|---|
| V1 | ✅ | `GET /mcdev/api/ping` → `{"ok":true,...}`；未知路径 → 404 |
| V3 | ✅ | bundle 以 `window.__ModuleLoader__.load` 包裹被服务端返回；`capsule: registered` |
| V3b | ✅ | `tabType/tabBody: registered`；1.5s 后 `expanded: true`、`activeTab.kind = mcdev.logs` |
| V7 | ✅ | 客户端 `fetch('/mcdev/api/ping')` 与 `POST /mcdev/api/report` 都通（同源、相对路径） |

## 5. 四个坑（已写进实现与策划）

1. **cordis 只把 `inject` 里声明的服务交给插件**。`ctx.get('sidebarRight')` 不算数：第一次跑时 `sidebarRight`/`sidebarRightTabs` 都取不到，改成 `exports.inject = ['slots', 'sidebarRight', 'sidebarRightTabs']` 后立刻正常。
2. **`openTab` 的展开是下一帧才生效**。调用后立刻 `isExpanded()` 仍是 `false`，1.5s 后才是 `true`。所以"启动即开日志"不能同步判断成功，只能等状态或直接看标签。
3. **pnpm 的 `file:` 会把本地目录拷贝一份**，改源码不生效。开发期用 `link:`（会建符号链接），发布时再用 `file:`/npm 版本。
4. **全局 `~/.dsh/cordis.patch.yml` 里的 MCP 条目会在每个 profile 生效**，本机 craftgraph 的 dist 不存在，于是启动日志里刷一屏 `Cannot find module`。与插件无关，但排查时容易被吓到。

## 6. 还没验的

- **胶囊的实际可见性**：slot 注册成功，但 `conversation.session.header.utilities` 由会话界面声明；没有打开会话时它只是排队等待。需要在浏览器里建一个会话后肉眼确认。
- **桌面版运行时**：M0 跑在 CLI web profile（0.1.5）上。桌面版 `DSH NEXT` 自带更新的运行时，client 包清单一致（都含 `dsh-client-ui-sidebar-right`），但要挂到 desktop profile 再验一次。
- **HMR / 热更新**：改 `lib/client.js` 后需要重启 profile 才会重新快照（bundle 在启动时快照）。M1 再看有没有更快的迭代方式。

## 7. 对策划的影响

- §12 的 M0 可以打勾，风险表里"客户端插件加载不起来"这一条可以降级。
- 仍保留"退回独立网页方案"的退路，但不再需要为它预留结构。
- 补一条新风险：slot 只在会话界面存在时可见，空会话/新手引导页看不到胶囊。
