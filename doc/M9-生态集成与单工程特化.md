# M9 生态集成与单工程特化

> 日期：2026-10-31 · 范围：better-sidebar 兼容、标签图标、面板命名、单工程形态。

---

## 1. 与 dsh-better-sidebar 兼容

better-sidebar 向所有插件开放 `ctx.betterSidebar.registerTab({ id, title, icon, component })`，
内置 tab 与第三方插件走同一套 API。我们向它注册两个页面：

| id | 标题 | 图标 | 组件 |
|---|---|---|---|
| `minecraft-dev-starter:project` | Mod Dev | 方块 | `DetailTab` |
| `minecraft-dev-starter:logs` | 运行日志 | 终端 | `LogTab` |

实现要点：

- **可选依赖**：better-sidebar 未必安装，也未必比我们早加载。首选 cordis 的作用域注入
  `ctx.inject(['betterSidebar'], (scoped) => …)`——服务出现才执行，不存在就静静等；
  拿不到 `ctx.inject` 时退回轮询 `ctx.get('betterSidebar', false)`，30 秒后放弃并上报
  `betterSidebar.absent`。
- **图标格式**：`descriptor.icon` 支持 ReactNode 或 `(size) => ReactNode`
  （`iconOf(icon, 16)` 里会调用函数），所以传 `(size) => h(IconCube, { size })`。
- **原生标签也保留**：没装 better-sidebar 的人照样能用右侧栏那两个标签。

## 2. 图标：为什么原生标签加不了

查了 0.2.1 的标签类型声明：

```ts
ctx.sidebarRightTabs.register({ id, kind, patterns?, priority?, canOpen?, title, guide?, keepMounted? })
```

**没有 icon 字段**，标题是纯文本；带字形的只有 guide 里的 entry capsule。
所以图标只出现在 better-sidebar 的标签上，原生标签保持文字。这不是偷懒，是接口没这个位置。

新增两个手绘字形（与既有图标同一套 16px / 1.3–1.5 描边）：`IconCube`（模组工程）、
`IconTerminal`（运行日志）。

## 3. 面板命名：从「MC 工程」到「Mod Dev」

原来的"MC 工程"是**名词描述**，不说明这个面板干什么；而且它和"工作区"、"会话"混在一句话里时，
读者分不清指的是目录还是功能。

`Mod Dev` 是**功能名**，和 IDE 里的 Run/Debug 一个性质：点了要看的是"这个模组怎么跑起来"。
现在这些位置统一用它：

- 原生标签标题、better-sidebar 标签标题；
- 浮层表头、浮层 `aria-label`；
- 详情页标题。

日志标签保持「运行日志」——它是描述性名词，读者一看就知道是什么。如果以后想要全英文，
把它换成 `Run Log` 即可，两处常量改一下就行（`PANEL_TITLE` 在 `client/format.js`）。

## 4. 单工程特化

工作区里只有一个工程时（最常见的情况），浮层不再渲染"列表"这一层：

```
改前                                改后
┌ 表头  Mod Dev          ⟳        ┌ 表头  Mod Dev            ⟳
│ C:\...\EnchatingPaper            │ EnchatingPaper
├ 列表  ● EnchatingPaper  NeoForge │ NeoForge · 1.21.1
│                                  │ C:\...\EnchatingPaper
├ 目标  运行目标  ◉ Client         ├ 目标  运行目标  ◉ Client
│              详情 ›              │              详情 ›
```

差别不在省一个像素，而在**语义**：多工程时"列表"意味着"要先选工程"；单工程时这层选择不存在，
画出来只会让人以为还有别的工程可选。表头直接承担工程身份（名字 + loader/版本 + 路径），
比多一行列表更短也更快。

多工程布局不变（上一轮的三段结构）。

## 5. 验证

```
node --test "test/*.test.js"   → 59 passed
```

客户端构建 53.3 KiB，`node --check` 通过。真机验证需要重启桌面版：

1. 右侧栏（better-sidebar）的 "+" 菜单里应出现 **Mod Dev**（方块图标）与 **运行日志**（终端图标）；
2. 打开 `EnchatingPaper` 这类单工程工作区，浮层应见不到列表、表头直接是工程名；
3. 原生右侧栏两个标签仍在（标题变成 Mod Dev / 运行日志）。

## 6. 已知限制

- 原生标签没有图标位（见 §2）。
- better-sidebar 未安装时，两个页面只在原生右侧栏里；不会为此报错。
- 两个页面共用同一份 `store`，所以在 better-sidebar 与原生标签里同时打开会看到同一份状态（这是想要的）。
