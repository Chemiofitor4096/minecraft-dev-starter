## 1. 怎么挂上去的

桌面版读的是 `~/.dsh/profiles/desktop`。改动很小：

1. 备份 `package.json` → `package.json.mcdev-backup`；
2. `dependencies` 加 `"minecraft-dev-starter": "link:C:/Projects/minecraft-dev-starter"`；
3. `dsh.profile.bundles` 末尾追加 `"minecraft-dev-starter"`；
4. 用**桌面自带 pnpm**（v11.28.5）`install`，确认 `node_modules/minecraft-dev-starter` 指向仓库。

回滚：还原备份的 `package.json` 再 `pnpm install` 即可。

## 3. 三个问题与根因

### 3.1 运行日志不同步（0 字节）

`~/.dsh/mc-dev-starter/logs/launch-6.log`、`launch-7.log` 都是 **0 字节**，但游戏正常跑完 70 秒。

最小复现（同一个 `gradlew.bat --version`）：

| spawn 选项 | 捕获字节 |
|---|---|
| `detached: true` | **0** |
| `detached: false` | 564 |

根因：Windows 上 `DETACHED_PROCESS` 与 `CREATE_NO_WINDOW` 是一对矛盾标志；组合后子进程的标准句柄不是我们给的管道，输出直接丢了。

修法：`detached` 只在 POSIX 上开（那里需要进程组来整组终止），Windows 上关掉、保留 `windowsHide`。修后同一个假工程拿到 6 行日志。

### 3.2 启动后多一个控制台窗口

同源：detached 的子进程没有可继承的隐藏控制台，`java.exe`（控制台子系统）只能自己开一个。关掉 detached 后子进程拿到 `CREATE_NO_WINDOW` 的隐藏控制台，后代理应继承它、不再弹窗。

**待真机确认**：这条只能由人看。如果仍出现，退路是把启动改到 DSH 的侧边栏终端里（`dsh-terminal`），代价是实例生命周期与终端绑定，"关掉 DSH 游戏还在"就不再成立。

### 3.3 `mc_projects` 报"0 个目标"

工具的输出值是紧凑形状（字段 `targets`），渲染函数却读 `runTargets`——于是永远读到空数组。工程本身识别是对的（`runClient/runServer/runGameTestServer/runData` 四个）。修：渲染读 `targets`，并在值里保留 `(推测)` 标记。

## 4. 指示灯状态（问答）

原来只有灰/绿/红三档，且"启动中"和"运行中"都是绿色。现在四档：

| 状态 | 颜色 | 呼吸 |
|---|---|---|
| 空闲（无实例） | 灰 | 否 |
| 启动中（building / 等就绪标记） | 黄（`state-warn`） | 是 |
| 运行中 | 绿（`state-success`） | 是 |
| 错误（扫描失败 / 启动失败 / 上次异常退出） | 红（`state-error`） | 否 |

## 5. 第二轮：日志有了，但标签不跟

关掉 detached 后重启：**控制台窗口不再出现**；新的实例 `launch-9`（01:28:24–01:29:08）日志 **10818 字节**、`outcome: normal`——采集链路本身通了。

但日志标签停在了 `launch-7`（01:19、0 字节、`killed`），显示"已停止 / （还没有输出）"。两个客户端问题：

1. **不跟随新实例**：旧逻辑只在"没选过"时挑一次，之后新实例不会顶上来。改成 `pickLogTarget()`：有实例在跑永远跟它（并解除手动固定）；用户手动选过就保持；否则跟当前/最新。
2. **状态文案混用英文**：下拉里 `Client · 01:19 · exited`，改成 `launchStatusText()` 统一中文（启动中/运行中/已停止/已退出/已退出(码)）。

顺带在真机上抓到第三个 bug：**`mc_launch_logs` 报 "value is not lossless JSON"**——返回值里带了 `undefined` 字段（`outcome`/`exitCode`/`diagnosis`/`pid`），注册器要求无损 JSON，整条拒掉。单测直接调 `execute` 绕过了这层校验，所以没发现。现在三个工具改为"只放存在的字段"，并加了 `assertLossless()` 断言兜住。

## 6. 会话切换不同步

现象：切换对话后，标题栏胶囊不会跟着换工作区（要等切回来或刷新页面才对）。

两个根因叠在一起：

1. **宿主用的是"最近创建的会话"**：`ctx.sessions.list().at(-1)` 是进程里最后创建的会话，不是界面上正在看的那个。切到旧会话后，默认工作区仍然指向最新那个。
2. **胶囊只在挂载时扫一次**：组件挂载后不再响应 `sessionId` 变化，所以即便切了会话也不会重扫。

改法：

- 胶囊改为按会话取 cwd：会话头 slot 会把 `sessionId` 与 `useSessions` 传给组件（`dsh-client-ui-open-in-app` 就是这么拿 cwd 的），订阅 `useSessions(s => s.byId[sessionId]?.cwd)`；cwd 变化时清掉旧扫描结果（避免闪现上一个工作区的工程）并按新 root 重扫。拿不到标准 props 时退回宿主默认。
- `loadScan` 默认用 `store.workspaceRoot`（胶囊写入），所有"刷新"按钮自动跟随当前会话。
- 启动校验从"落在唯一工作区内"改为"落在任意活跃会话的 cwd 之内"——否则切到另一个工程的会话后，点启动会被误判越界。
- 工具也改用**调用它的那个会话**的 cwd（`exec.agent.session.header.cwd`），不再依赖宿主默认。
