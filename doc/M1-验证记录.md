## 3. 真实工程回归

`node scripts/scan-catalog.mjs C:\Projects` → 22 个工程、97 个目录、**76ms**。

顶层 17 个工程的判定：

| 类型 | 数量 | 例子 |
|---|---|---|
| Forge（含 moddev **legacyforge**） | 8 | `TinkersAssembly`、`tmachines`、`Create-Cooling-Fan` |
| NeoForge（moddev） | 5 | `rationality`、`EnchatingPaper` |
| Fabric | 1 | `BurstDoorOpen-fabric-1.21.1` |

另有 3 个嵌套工程被扫出来（`craftgraph/mod`、`craftgraph/mod-1.20.1`、`hoa/bdo`、`hoa/fs`）——它们所在的父目录本身不是工程，属正常结果。

### 3.1 修正了一个此前的误判

策划 v0.2/附录 B 曾写"13 个 NeoForge"。实测发现其中多数用的是 `net.neoforged.moddev.legacyforge`——这是 NeoForge 团队维护的**构建工具**，产物是 **MinecraftForge 1.20.1 模组**（`forge_version=47.x`）。识别引擎按"插件是否 `legacyforge`/`net.minecraftforge.gradle` 决定 Forge"来判，这批正确落在 Forge 上。

结论：**看构建插件，不看组织名**。这条已写进判定表注释。

## 4. 两个真实工程逼出来的修正

### 4.1 聚合仓库的 loader 只在子模块里

`AnnoCore` 根 `build.gradle` 只有 `allprojects { ... }`，没有插件；`fabric-loom` / `net.neoforged.moddev` 全在 `anno-mod-*` 子模块里。第一版只读根脚本 → 判成 `unknown`。

修正：先看根，根没有再看子模块；同时记录 `loaders[]`，多于一种就把 kind 升级成 `multi-loader`。修正后 `AnnoCore` = `multi-loader`，4 个平台模块各出一个 Client 目标。

### 4.2 推测目标不能刷屏

修正前 `AnnoCore` 因为 6 个模块各补 Client/Server/Data，列出 **19 个推测目标**。规则改成：

- 单模块工程 → 给完整默认集（Client/Server[/Data]）；
- 多模块工程 → 每个平台模块只给一个 Client；
- `common` 模块永远不猜（它通常没有客户端）。

现在 4 个，且全部带 `guessed: true`，浮层里显示为灰字。

## 6. 已知限制

1. **没有会话时标题栏胶囊不可见**。`conversation.session.header.utilities` 由会话界面声明；空工作台只注册不渲染。M1 用 `DEV_AUTO_OPEN` 自动打开详情标签来验证面板（`src/client/index.js`，M3 关掉）。
2. **扫描根取"最近活跃会话的 cwd"**，没有会话时退回宿主进程 cwd。测试 profile 里存在一个旧会话（cwd = 本仓库），所以面板显示的是仓库里的 4 个 fixture 工程，而不是 `C:\Projects`。真机上打开哪个工作区就扫哪个。
3. **聚合仓库的版本可能读不出来**：`AnnoCore` 根 `gradle.properties` 没有 `minecraft_version`，模块也没有，于是 MC 版本显示 `?`。这里选择诚实留空，不猜。
4. **不执行 Gradle**：`Custom-Machinery` 这类没写 `runs {}` 的工程只能给推测目标（灰字），用户可以在浮层里看到"未验证"。按需要的探测能力留到 M2。
